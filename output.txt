AFTERWARD (post-discharge-mcp): CODEBASE SUMMARY
Written 13 October 2026, at commit f3353ce on main.


1. WHAT THE PROJECT IS
======================

Afterward is a post-discharge companion. A patient's hospital discharge letter
(PDF or photo) is uploaded, read by a model on Amazon Bedrock, and turned into:

  - a structured recovery plan: medicines, tasks, appointments, restrictions,
    things to monitor and warning signs, saved in DynamoDB;
  - searchable source text: the letter's own passages, stored in S3 Vectors,
    so answers can quote the paperwork.

On top of that sit an MCP server that exposes the plan as tools, a
conversational agent that uses those tools, a reminder engine, and a Next.js
demo UI that simulates a voice assistant ("Simulated Alexa+").

Everything runs in AWS region eu-west-2. Licence: MIT.


2. HOW THE PIECES CONNECT
=========================

Document ingestion (deployed):
  S3 upload -> SQS queue -> document_processor Lambda -> extract text ->
  Bedrock structured extraction -> normalise and validate -> save RecoveryState
  to DynamoDB -> index the pages in S3 Vectors -> mark the document "ready".

Using the plan (local or deployed):
  Browser UI (Next.js, port 3000)
    -> web bridge (Python, port 8002)
    -> agent (Bedrock model + safety rules)
    -> MCP server (port 8000 locally, or the CloudFront deployment)
    -> DynamoDB and S3 Vectors.

Reminders:
  An EventBridge schedule calls the reminder_checker Lambda, which picks the
  next due item and writes a reminder into RecoveryState. Locally, the web
  bridge can run the same handler in a loop.


3. WHAT EACH FOLDER CONTAINS
============================

app/                      The Python application (66 tracked files).
  agent/                  The conversational agent: prompts, intent detection,
                          session state, safety and crisis handling, symptom
                          and food answers, dose answers, evidence (which
                          letter passage backs an answer), the "next up" list,
                          and completion replies. service.py is the main loop.
  mcp/                    The MCP server (server.py, http_server.py), its HTTP
                          auth, a client, and the tool implementations.
                          Seven tools: get_recovery_plan, get_today_tasks,
                          get_medications, search_discharge_instructions,
                          report_task_completed, report_medication_taken,
                          undo_report.
  ingestion/              Letter processing: PDF and image text extraction,
                          Bedrock extraction, schemas, normaliser, validator,
                          upload validation, patient-name handling, pipeline.
  rag/                    Chunking, Titan embeddings, S3 Vectors store, search.
  reminders/              Reminder config, engine, selector and wording.
  database/               DynamoDB access: recovery_state.py (the current
                          plan and today's occurrences) and event_history.py
                          (what the patient has reported doing).
  auth/                   MCP token checks and per-patient scoping.
  aws/                    S3 and SQS helpers.
  models/                 The RecoveryState dataclasses.
  observability/          Structured logging.
  clock.py                Shared clock; CLOCK_MODE=demo pins "now" to
                          DEMO_FIXED_NOW for recordings.
  config.py               Environment settings and model selection.
  web_bridge.py           The local HTTP bridge the UI calls (/today, /chat,
                          /reminders/check, upload validation, history reset).
  safe_logging.py         Keeps patient data out of logs.

web/                      The Next.js 16 / React 19 UI (41 tracked files).
  app/page.tsx            Upload page: send a letter and watch it process.
  app/demo/               The main demo: Today screen, voice panel, letter
                          panel, Get help card, Developer view.
  app/assistant/          Assistant page.
  app/api/                Server routes: upload, recovery-state, today, chat,
                          reminders/check. They call S3/DynamoDB or the bridge.
  lib/                    AWS clients, bridge address, polling, check-ins,
                          speech and voice, spoken-text formatting, upload
                          validation, request IDs.
  tests/                  7 TypeScript test files (no AWS calls).

lambdas/                  Lambda entry points: document_processor and
                          reminder_checker.

AfterWardMCP/             An Amazon Bedrock AgentCore project (CDK stack,
                          agentcore.json, a small main.py) for hosting the
                          MCP server.

deployment/               Lambda environment files, IAM trust and permission
                          policies, the reminder schedule target, pinned
                          Lambda dependencies, and name-migration/ (records of
                          the CareLoop -> AfterWard resource rename).

infra/                    security/: IAM, KMS and S3 bucket policies,
                          encryption, lifecycle and public-access settings.
                          observability/: a CloudFormation template.

scripts/                  Manual checks and operations (49 files):
                          run_web_bridge.py, reset_demo_patient.py, MCP and
                          agent smoke tests, plus aws/, deployment/,
                          ingestion/, rag/, security/ and letters/ subfolders.

tests/                    Python tests (58 files) grouped as agent, auth, aws,
                          database, ingestion, mcp, rag, plus reminder, clock,
                          logging and end-to-end tests at the top level.

docs/                     REPOSITORY_GUIDE.md, architecture.md (+ .svg),
                          aws-integrations.md, aws-name-migration.md,
                          aws-setup.md, observability.md, testing.md.

phase15/                  A snapshot of the demo UI at phase 15, with three
                          screenshots and a README.

test_data/                Synthetic discharge documents (doc_001.pdf etc.).

lambda_package/           A vendored copy of the app and its dependencies for
                          the Lambda build. 2,463 of the repo's 2,779 tracked
                          files are here.

Top-level files:
  README.md, LICENSE, Dockerfile, requirements.txt, pytest.ini, .env.example
  ecs-task-definition.json, cloudfront-config.json   deployment config
  check_setup.py, list_models.py, verify_models.py   AWS and model checks
  run_ingestion.py                                   run the pipeline locally
  careloop_document_processor.zip                    old Lambda archive (20 MB)
  lambda-smoke-response.json                         saved smoke-test output

Note: docs/REPOSITORY_GUIDE.md still says "MCP server: not implemented" and
"no single app server command". Both are out of date; the MCP server, agent,
bridge and UI all exist now.
